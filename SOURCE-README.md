# AURA v0.12 — исходный код

Windows x64 приложение на .NET 8/WPF: цветовые профили мониторов, прицел, PresentMon-замеры, диагностика, Windows Tuner и ограниченная аппаратная автонастройка. Эта сборка для разработки не подписана Authenticode. По умолчанию используется явно обозначенный прототип авторизации.

## Изменения v0.12

- Карточки игр объединяют выбранный цвет, отдельный прицел, конфигурацию оверлея и монитор. Можно возвращать общие настройки при Alt-Tab или сохранять игровые до завершения процесса. Старые привязки цветов остаются совместимыми.
- Временные игровые цвета имеют отдельный DPAPI-снимок перед записью. Сохраняются фактическая гамма и целочисленный NVIDIA DVC, включая прежний активный монитор. Возврат проверяется чтением; незавершённый снимок не перезаписывается. Старые снимки v0.11 с нормализованным DVC продолжают поддерживаться.
- Внешний игровой оверлей показывает PresentMon FPS/1% low с целевым окном примерно 2 секунды, график времени кадров и датчики. Есть выбор угла, размера, непрозрачности и показателей. Инъекции в игру нет; эксклюзивный полноэкранный режим и правила конкретной игры требуют отдельной проверки.
- Глобальные настраиваемые клавиши переключают прицел/оверлей, запускают или отменяют замер, выбирают следующий цветовой профиль и возвращают исходные цвета. Конфликт регистрации виден в настройках.
- Серии по 3/5 отдельных прогонов сохраняют сцену, графику, версии игры/драйвера, оборудование, Windows, режим монитора и длительность. Запись датчиков продолжается при свёрнутой AURA. Сравнение проверяет одинаковые условия, полноту и длительность записей, показывает средние и диапазоны всех прогонов. Выбросы не удаляются автоматически.
- Живой FPS разделяет PID/swapchain, исключает сгенерированные кадры и обрабатывает неполные строки CSV. При отсутствии свежих строк отображается прочерк. Отрисовка не ждёт зависшего запроса датчиков; устаревшие FPS и показания скрываются. Кэш динамических температур/нагрузки/частот/мощности/использованной VRAM очищается перед обновлением драйвера. Временные CSV удаляются; отмена завершает только собственную ETW-сессию. Во время замера оверлей использует тот же поток захвата.
- До первой записи настроек старой схемы сохраняется копия `settings.pre-v0.12-*.json`. Названия режимов Windows Tuner описывают объём изменений: Минимальный/Сбалансированный/Расширенный.

Инструкции по новым функциям: [docs/Gaming-Guide.md](docs/Gaming-Guide.md). Аппаратная яркость DDC/CI, ICC/HDR-калибровка, библиотека магазинов, управление вентиляторами и новый рендерер масштабирования относятся к последующим этапам. Смена разрешения сейчас выполняется вручную с существующим 15-секундным подтверждением.

## Изменения v0.11

- Исходные Intel PL1/PL2 и NVIDIA P0 offset сохраняются до записи; повторное применение профиля использует абсолютные значения. Возврат проверяется чтением; потеря температурного контроля останавливает тест. Старые температура/нагрузка в кэше библиотеки очищаются перед запросом: ошибка драйвера не подменяется прежним показанием. Данные восстановления привязаны к устройству и загрузке Windows, защищены DPAPI.
- GPU-тест проверяет вычисления и измеренную нагрузку на том же физическом GPU. CPU-тест проверяет результат вычислений. Есть расширенная проверка, история и отдельный выбор автоприменения. Это не доказательство стабильности во всех играх.
- Запись AMD PBO отключена: встроенный адаптер не позволяет надёжно сохранить исходные лимиты. Intel также отказывает при блокировке BIOS, отсутствии диапазона или датчиков.
- Windows Tuner использует защищённый журнал до изменений, проверяет результат и возвращает записанное исходное состояние. При частичной ошибке снимки остаются. Есть предварительный список изменений, статусы и история. Из 82 определений 5 недоступны: четыре удаления AppX без доверенного MSIX-источника и отключение гибернации без точного восстановления типа/размера файла. Профили Low/Medium/Ultra содержат 25/41/61 пункт; они не включают Danger.
- Диагностика различает ошибки доступа и отсутствие событий; события группируются по провайдеру и ID. CSV разбирается отдельно по процессам/swapchain, длинные задержки сохраняются. Есть график, история, сравнение и экспорт без данных входа и идентификаторов устройства.
- Ручной профиль возвращается после ухода игры из активного окна. Профили можно создавать, обновлять, переименовывать, удалять, импортировать и экспортировать. Удалённые игровые привязки не появляются вновь. Сохранение настроек сгруппировано с задержкой.
- Восстанавливаются исходные гамма/Vibrance и индивидуальная настройка NVIDIA-профиля. Смена разрешения требует подтверждения за 15 секунд. Масштабирование имеет сохранённую базу. Прицел и превью используют общий рендер; мониторное окно учитывает DPI. Обрабатывается подключение мониторов.
- Реализованы локальный сервер лицензий, клиент с закреплённым открытым ключом, проверка срока во время работы и ограниченный подписанный офлайн-доступ. Подробности: [server/README.md](server/README.md).
- Добавлены закреплённые SDK/зависимости, решение, регрессионные тесты, CI, проверка обновлений и генерация отчёта текущего выпуска.

## Разработка и сборка

Нужен SDK из `global.json` (8.0.425). На Linux можно собирать Windows-цель и выполнять переносимые тесты; запуск WPF и аппаратные операции требуют Windows.

```powershell
dotnet restore Aura.sln --locked-mode
dotnet build Aura.csproj -c Release --no-restore
dotnet run --project tests/Aura.CatalogSmoke -c Release --no-restore
dotnet test tests/Aura.RegressionTests -c Release --no-restore
dotnet test tests/Aura.AuthTests -c Release --no-restore
./tests/Aura.PowerShellSmoke/Smoke.ps1
./scripts/build-release.ps1
```

Release-скрипт прекращает работу при ненулевом коде команды, проверяет четыре встроенных компонента по SHA-256, запускает тесты и создаёт новый `release-v0.12` с `app/Aura.exe`, результатами тестов, лицензиями и `release-report.json`. Существующий каталог выпуска сохраняется; для повторной сборки укажите новый `-OutputDirectory`.

`-Expanded` создаёт сборку с отдельными DLL для замены сторонних библиотек и повторной компоновки. Исходный проект и lockfiles позволяют пересобрать EXE с изменённой LGPL-библиотекой. Для выпуска с подписью на Windows используйте `-SigningThumbprint <отпечаток установленного сертификата> -RequireSigned`; нужны сертификат в защищённом хранилище и `signtool` из Windows SDK. Пароли и ключи в код не добавляются.

## Прототип и серверная авторизация

В прототипе: `demo@aura.app`, пароль `aura2026`, ключ `AURA-30D-DEMO-2026`. Это тестовая активация с локальным сроком, не оплаченная подписка и не защита коммерческой лицензии. Демо-данные не принимаются сервером без явно созданного аккаунта/лицензии.

Серверная сборка читает конфигурацию, встроенную при сборке. Настройте её через `scripts/configure-auth.ps1`; в режиме Server обязателен HTTPS, открытый ключ задаётся разработчиком и не скачивается от сервера. LocalDevelopment допускает HTTP только на loopback. После изменения нужен новый EXE. Не публикуйте коммерческую сборку в режиме Prototype или LocalDevelopment.

## Проверка на Windows

Список: [RELEASE-CHECKLIST.md](RELEASE-CHECKLIST.md). Проверки в этой облачной среде не подтверждают UAC, DPAPI, NVAPI, гамма-кривые, масштабирование, Direct3D, датчики, стабильность железа и смешанный DPI. Точки восстановления Windows могут быть недоступны; основной механизм возврата — журнал AURA. Успешная запись политики не означает, что редакция Windows использует её.

Аппаратные параметры не прошиваются в BIOS. При неподтверждённом возврате сохраните журнал и верните исходные параметры/перезагрузите Windows. Иллюстрации сцен не показывают результат обработки настоящего монитора. BIOS Guide содержит примеры меню ASUS TUF A520M-PLUS; модель платы не определяется автоматически.

Компоненты, лицензии и возможности повторной сборки: [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md).

Снимки твиков v0.10 в `%ProgramData%\AURA\Tweaks` обнаруживаются и сохраняются отдельно. Новый журнал их автоматически не исполняет; он фиксирует состояние перед изменениями v0.11. Параметры, которых старая версия не сохраняла, нельзя восстановить по придуманным значениям.
